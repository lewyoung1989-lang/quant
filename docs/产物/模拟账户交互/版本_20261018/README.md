# 红利研究交易与收益核对 · 2026-10-18

用户反馈「ERP 没有大于 35%，为何是 100% 仓位」，并要求连同交易曲线和收益率重新检查。本批次已本地修正并验证，未推送 GitHub、未远程部署；10 月 17 日的历史方案与验证原样保留。

## 核实结论

9 月 4 日交易使用 9 月 3 日信号，ERP 为 37.2%，因此目标仓位 100%。旧交割单错误引用成交当天的 32.4%，又只按买卖方向套用「>35%」或「≤20%」说明，导致明显矛盾。默认中性仓位为 75%；截图中的 50% 不是此次默认参数回放值，未据截图推断其当时全部配置。

另发现旧收益计算将新仓位用于成交日整段收盘涨跌，与账单的当日收盘成交价不一致；只按红利腿目标仓位差计费用，未完整计入国债腿和首次建仓；目标不变时以固定权重计算收益，相当于未计费用的再平衡。年度统计又漏掉跨年首个交易日收益。

## 修正口径

- 前一交易日信号，次日收盘参考价成交；当日调仓前按原份额计算涨跌。
- 起点为现金，次日首次建仓；使用可分割份额的研究模型，不执行整数手模拟账户交易。
- 每笔买卖按成交额收取配置成本，红利与国债分别计费；交易后资金守恒。
- 目标不变时持有原份额，实际仓位随价格漂移。曲线分别展示目标与实际收盘仓位。
- 账单增加信号日期，三档依据按实际指标与报告中记录的阈值生成；ATR、BIAS/RSI 同样使用前日指标。
- 减仓收益按加权成本及红利买卖费用计算，改称「减仓盈利比例」「减仓笔数」，不再声称完整做 T 胜率。它不等于含国债的组合总收益。
- 年度收益由每日收益复合，纳入跨年首日。指标图阈值随设置变化，修复此前固定 80% 参考线。
- 所有视图复用同一份行情快照，移除页面中途再次拉取数据造成的混用。
