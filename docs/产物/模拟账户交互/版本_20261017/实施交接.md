# 模拟账户交互 Demo 的实施交接

本文件保留原型交付时的接入建议与当时状态。后续用户已确认方案并授权实施；本地改造现已完成，最终实现与验证见[正式接入说明](正式接入说明.md)。下文「未执行」等措辞均描述原型阶段，不代表当前状态。

## 页面与业务对象

| 页面区域 | 正式业务映射 |
| --- | --- |
| 账户列表 / 搜索 | 读取账户 ID、名称、策略、资产与运行状态；名称只用于展示 |
| 新增账户 | 创建空仓账户、初始资金流水、显式策略绑定与参数版本 |
| 资金管理 | 事务内校验并更新可用现金、净投入和出入金流水 |
| 账户设置 | 保存名称、策略 ID / 版本、参数、自动执行开关与运行状态 |
| 持仓表 | 实际模拟持仓、可卖数量、价格与估值时间 |
| 今日调仓 | 后端返回信号、持仓差额、委托依赖、限制原因和计划版本 |
| 成交记录 | 正式执行记录，而非通过回测收益反推的成交 |
| 运行记录 | 配置修改、计划生成、阻断、执行和错误事件 |

现有 `services/rebalance_service.py` 可作为接入起点。`get_all_accounts` / `save_current_position` / 生成与执行函数需复用业务逻辑；逐步用稳定 ID 和显式 `strategy_type` 替代以账户名称猜测策略。当前生产逻辑没有因本 Demo 自动获得这些修复。

## 需要保持的交互语义

- 创建新账户不覆盖已有同名账户，返回字段错误；独立 ID 不随重命名变化。
- 修改初始资金与普通出入金分开。已有运行账户采用出入金流水管理，不用重置持仓代替入金。
- 保存策略不静默卖出持仓。先给出新计划与差额，手动账户由用户发起执行。
- 交易锁和幂等必须位于服务端，不能依赖按钮置灰。提交时绑定账户版本、计划版本和行情快照。
- 卖出失败或部分成交时，买入依赖必须重新校验，不能把未成交所得算作可用现金。
- 执行结果返回后同时更新资产、持仓、清单与记录，保留执行失败和部分完成状态。
- 暂停状态必须由执行服务校验；自动开关启用不绕过交易时段和行情质量条件。

## Demo 与正式业务的区别

Demo 的例示撮合不是生产执行实现。正式接入需使用实际交易日历、行情时间与来源、分红复权口径、标的交易单位、实际可卖数量、费用、滑点与依赖关系。

当前代码存在手动强制执行与前端时段显示可能不一致的情况。接入时应统一到后端门禁，不能直接照搬 `force_auto=True` 作为绕过条件的通用按钮行为。

自动执行必须有独立后台调度与可靠持久化；关闭浏览器不影响已配置任务。Demo 中「打开页面、切换情境或刷新才执行」是为了体验状态，不是正式调度方案。

原项目文档中尾盘决策与执行窗口的表述存在 14:45–14:50 和 14:45–14:55 两种粒度。Demo 沿用当前页面的 14:45–14:55；正式接入需要明确决策截止、计划固定与执行窗口的关系，不能由视觉改造擅自改写交易语义。

收益金额与出入金隔离。需要比较跨账户或跨时间业绩时，补充经验证的收益统计方法与适用范围；不能把简单净投入比例当作时间加权业绩。

## Streamlit 接入建议

可先以账户选择列表、`st.dialog` 或显式账户设置区、五个同级标签和统一状态区映射 Demo。若无法完全复刻侧边面板，以正确的账户上下文、阅读顺序和状态反馈为准。

复用已有策略研究入口和报告，不因为本次模拟账户改造删除回测能力。因子与模型在没有正式模拟运行服务前保持研究入口，不伪装成可运行的自动交易策略。
